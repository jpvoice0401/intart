# MineCraft 바닥 AR — 8th Wall

MineCraft의 `바닥 AR`에서 다이아몬드 검을 배치할 수 있습니다. 카메라 게임에서 같은 대상에게 10번 명중하면 대상이 화면에서 사라지고, 버튼 이름이 `모습 AR 배치`로 바뀝니다. 이 버튼으로 보관한 모습도 다른 위치에 놓을 수 있습니다.

## 사용

1. 사용자가 개발 PC에서 `npm.cmd run dev`를 실행합니다. 에이전트는 서버를 실행하지 않습니다.
2. 같은 네트워크의 **휴대폰/태블릿**에서 개발 서버가 출력하는 **HTTPS Network URL** 뒤에 `?example=minecraft`를 붙여 엽니다. 휴대폰의 localhost는 개발 PC 주소가 아닙니다.
3. `바닥 AR`을 누르고 카메라·기기 동작/방향 권한을 허용합니다. iOS의 동작 권한은 버튼을 누른 시점에 먼저 요청합니다.
4. 후면 카메라로 밝고 무늬가 있는 바닥을 천천히 비춥니다. 설치할 수평 영역이 확인되면 녹색 링과 설치 버튼이 활성화됩니다.
5. 바닥을 직접 터치하거나 `여기에 설치`를 누르면 그 위치에 검이 눕혀지거나 보관한 모습이 수직으로 세워집니다. 폰을 움직여도 배치된 월드 좌표는 유지합니다.
6. `크기`, 회전 버튼, `다시 설치`로 조정합니다. 재설치 시 기존 월드 추적을 재시작하거나 원점을 옮기지 않습니다.
7. `게임으로 돌아가기`/Escape로 AR을 종료합니다. 후면 카메라·SLAM을 정리한 뒤 기존 카메라 게임을 다시 켤 수 있습니다.

개발용 HTTPS 인증서의 CA는 접속하는 기기에서도 신뢰해야 합니다. 인증서 경고를 무시하는 것만으로 카메라/동작 권한이 동작한다고 보장할 수 없습니다. 가능하면 최신 Safari/Chrome의 외부 브라우저로 열어주세요. PC에서는 실제 바닥 추적을 시작하거나 가짜 바닥 배치를 제공하지 않습니다.

## 현재 8th Wall 연동 방식

웹 조사 결과 현재 공식 엔진은 로컬 포함 방식을 제공합니다. 과거 호스팅 플랫폼의 app key/로그인 방식을 사용하지 않습니다.

- [공식 엔진 통합 안내](https://8thwall.org/docs/engine/overview)
- [공식 배포 패키지/라이선스](https://github.com/8thwall/engine)
- [XR8 실행과 후면 카메라](https://8thwall.org/docs/api/engine/xr8/run)
- [월드 추적 결과와 4×4 카메라 투영 행렬](https://8thwall.org/docs/api/engine/xrcontroller/pipelinemodule)
- [hitTest](https://8thwall.org/docs/api/engine/xrcontroller/hittest)

`@8thwall/engine-binary@1.0.0`을 정확한 버전으로 설치하고 배포 파일을 `public/vendor/8thwall/`에 원본 그대로 복사했습니다. SDK는 수정/역공학하지 않습니다. 원본 LICENSE와 README를 보존하며 `provenance.json`은 파일별 크기와 SHA-256을 기록합니다.

원본 엔진 파일을 다시 복사해야 하면 다음만 실행합니다. 이 명령은 서버를 실행하지 않습니다.

```powershell
npm.cmd run setup:ar
```

AR 버튼을 누를 때 로컬 `xr.js`와 SLAM 청크만 로딩합니다. 다른 예제나 일반 MineCraft 화면에서는 엔진을 미리 불러오지 않습니다. 얼굴/하늘 효과 청크나 계정 키를 사용하지 않습니다. 정적 배포에는 `dist/vendor/8thwall/` 디렉터리도 포함해야 합니다.

바이너리는 MIT가 아닌 **XR Engine License Agreement** 적용 대상입니다. 원본 notices를 그대로 보존하고 AR 화면에 제작사/저작권/라이선스/AS IS 링크를 표시했습니다. 원문은 `public/vendor/8thwall/LICENSE`입니다.

## 구현과 실제 바닥 판정

- `minecraft-ar-engine.ts`: 공개 API 타입, iOS 동작 권한, 로컬 엔진/SLAM 로딩. 엔진을 실행하거나 카메라를 여는 것은 사용자 AR 버튼 동작 이후입니다.
- `minecraft-ar-placement.ts`: 추적 결과로부터 수평 바닥을 선택합니다. 아래 조건을 만족하는 데이터가 없으면 설치를 허용하지 않습니다.
- `minecraft-ar.ts`: AR UI, 후면 카메라, SDK 파이프라인, 설치·회전·크기·재설치와 자원 정리.
- `scripts/setup-minecraft-ar.mjs`: 고정된 패키지의 배포 파일 복사/해시 기록.

8th Wall `XrController`의 SLAM을 활성화하고 absolute scale을 사용합니다. `NORMAL` 추적 상태에서만 설치를 허용합니다. 카메라보다 낮고 거리 0.15–8 범위의 추적된/추정된 수평 surface를 우선합니다. surface quaternion의 법선이 world up과 일치하는지 확인합니다.

직접 surface가 없으면 실제 feature point를 중앙/주변에서 샘플링하여 바닥을 추정합니다. 최소 3개의 점이 독립적인 두 방향으로 펼쳐져 있어야 하며, 투영 면적, 중력 방향과의 법선 정렬, 평면 오차를 확인합니다. 화면 좌표에 고정한 가짜 물체, 임의의 y=0 바닥, 클릭 위치를 무조건 설치 위치로 쓰는 fallback은 없습니다. 수평면은 바닥 외에도 탁자 등을 포함할 수 있으므로 사용자가 카메라로 실제 바닥을 겨눠야 합니다.

카메라 프레임은 SDK의 GlTextureRenderer로 그리고 같은 WebGL2 컨텍스트에 프로젝트의 Three.js 렌더러를 연결합니다. SDK의 공개 `position`/`rotation`/16차원 `intrinsics`를 장면 카메라에 적용하고, 그 위에 깊이 버퍼만 지운 뒤 검을 그립니다. 전역 THREE를 덮어쓰거나 기존 Three.js 버전을 바꾸지 않습니다.

검은 기존 픽셀 윤곽 3D 메시를 재사용하며 AR에서는 팔을 추가하지 않습니다. 검 메시의 바운딩 박스를 계산해 가장 낮은 면이 바닥과 맞닿도록 배치합니다. 한 번 설치한 객체는 카메라나 조준 링에 계속 붙이지 않습니다. 추적이 제한되면 임의 위치로 이동시키지 않고 숨겼다가 추적이 회복되면 다시 표시합니다.

명중 대상은 첫 타격의 조준점에 닿는 사람 영역에서 시작해 이전 프레임과 겹치는 윤곽을 따라갑니다. 10번째 타격에서는 같은 프레임의 영상과 사람 마스크로 배경이 투명한 컷아웃을 보관합니다. 원래 화면에서는 해당 영역을 앞서 관측한 실제 배경으로 바꾸며, 한 번도 보이지 않은 부분은 주변 배경 텍스처를 찾아 이어 붙입니다. 사라진 후에도 실제 배경을 계속 학습해 추정값을 교체합니다. 카메라를 고정하고 잠시 빈 공간을 보여주면 그때 관측한 공간을 그대로 사용할 수 있습니다. 처음부터 가려졌던 물체까지 정확히 복원하는 방식은 아닙니다. 자세한 처리와 한계는 [공간 복원 설명](./MINECRAFT.md)에 있습니다. 사람끼리 붙어 있으면 분할 모델이 하나의 윤곽으로 인식할 수 있습니다.

보관한 모습은 AR에서 기본 높이 1.55m의 평면으로 세웁니다. 컷아웃은 현재 페이지 메모리에 두므로 전면 카메라에서 후면 AR로 전환해도 사용할 수 있습니다. 새로고침하거나 예제를 나가면 사라지며, 초기화 버튼으로 지울 수 있습니다.

## 성능과 생명주기

- 일반 카메라와 MediaPipe를 먼저 종료하여 AR 카메라/SLAM과 동시에 실행하지 않습니다.
- SDK가 카메라 프레임 루프를 소유하고 별도의 AR rAF를 만들지 않습니다. 설치 위치 탐색은 약 7Hz 이하이며 설치 후에는 중단합니다.
- DPR 최대 1.5, AR 그리기 버퍼 최대 1600×1200. 검은 단일 정적 메시이고 얼굴/조명/포인트클라우드 반환을 추가 활성화하지 않습니다.
- 탭 숨김 시 SDK를 pause하고 재표시 시 resume/추적 재확인을 합니다.
- AR 종료/예제 전환/시작 중 취소 시 SDK stop, 해당 모듈 제거, 이벤트/ResizeObserver/타이머, 메시/재질/GPU 컨텍스트와 UI를 정리합니다. 엔진 로딩 도중 취소해도 로딩 완료 후 카메라를 다시 열지 않게 상태를 검사합니다.

## 검증 범위

2026-11-19: `npm.cmd run setup:ar`, `npm.cmd exec tsc -- --noEmit`, `npm.cmd run build` 모두 통과(종료 코드 0). `node --check scripts/setup-minecraft-ar.mjs`도 통과했습니다. 개발 서버/미리보기 서버와 모바일 카메라를 실행하지 않았습니다.

정적 검사에서 SDK 배포 파일 13개의 node_modules 원본/public/dist 바이트 및 provenance 해시 일치, 고정 SDK 버전, 기존 dev/build 명령·15개 예제 등록·기본 경로 유지, 엔진의 조건부 로딩, 실제 카메라 pose/projection 연결, 설치 시 한 번만 객체의 월드 위치를 갱신하는 것을 확인했습니다. 기존 무손실 gzip/Brotli 빌드 압축도 완료했습니다. 초기 파일 검사 스크립트의 Windows 기본 cp949 디코딩 오류는 명시적 UTF-8 읽기로 수정해 재검사했습니다.

스마트폰에서 실제 바닥 추적·권한 흐름·공유 WebGL2 표시·설치 안정성·발열은 아직 직접 확인하지 않았습니다. 모든 인앱 브라우저에서 동작하거나 바닥/스케일 추정이 항상 정확하다고 검증한 상태는 아닙니다.
