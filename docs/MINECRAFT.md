# MineCraft

15번째 예제. `https://localhost:5174/?example=minecraft` 또는 메뉴의 검 아이콘으로 엽니다.
개발 서버는 사용자가 `npm.cmd run dev`로 실행합니다. 기존 기본 예제(rolex)와 다른 예제의 동작/설정은 유지합니다.

추가된 `바닥 AR`은 8th Wall의 후면 카메라 월드 추적으로 검을 바닥에 설치하는 별도 모드입니다. 사용법과 연동/검증 범위는 [MINECRAFT_AR.md](./MINECRAFT_AR.md)에 있습니다.

## 조작과 화면

- 카메라를 켜면 거울처럼 반전한 실시간 영상 위에 3D 다이아몬드 검과 Steve 스킨의 블록 팔, 중앙 십자 조준점, 9칸 핫바, 체력/방어력/허기/경험치 HUD가 표시됩니다.
- 인벤토리에는 다이아몬드 검 하나만 들어 있고 첫 슬롯이 선택되어 있습니다. 아이템 이름과 내구도 막대도 표시합니다.
- 시작 안내 카드와 상태 문구·아이템 이름·HUD는 하나의 그리드에서 공간을 나누어 글자가 겹치지 않습니다. 낮은 화면에서는 안내를 축약하고, 공간이 더 부족하면 카드 안에서 스크롤할 수 있습니다. 방어력·체력·허기는 동일한 9×9 픽셀 칸에 겹치지 않게 배치합니다.
- 클릭/터치하면 해당 방향으로 검을 휘두릅니다. Space는 중앙 방향으로 공격합니다. 클릭한 위치로 조준점 자체를 이동하지 않습니다.
- 명중은 **중앙 조준점**으로만 판정합니다. 조준점이 350ms 이내의 최신 사람 마스크에서 confidence 0.55 이상인 경우 명중합니다. 카메라 cover 크롭과 좌우 반전을 감안해도 중앙은 원본 카메라 중앙으로 대응합니다.
- 명중하면 사람 마스크 안쪽만 짧게 빨갛게 표시합니다. 배경과 검/HUD에는 색을 씌우지 않습니다. 마스크 가장자리는 confidence로 부드럽게 연결하고 사람을 계속 따라갑니다. 사람 인식이 오래되면 피격 효과를 중단합니다. 여러 사람을 분리하는 instance segmentation은 아닙니다.
- `E`/인벤토리 버튼으로 인벤토리 창을 열고 `E`, `Escape`, 닫기 버튼 또는 창 바깥 클릭으로 닫습니다. 창/툴바/메뉴 클릭은 공격으로 처리하지 않습니다.
- `Aa`는 안내 표시, `↺`는 공격 효과 초기화, 카메라 버튼은 시작/종료입니다. 카메라 없이도 검 휘두르기를 볼 수 있지만 명중은 발생하지 않습니다.
- 공격 초기 절반 동안의 중복 입력은 동작을 끊지 않으며 이후 입력은 새 공격으로 시작합니다. 자동 연타/무한 대기열은 만들지 않습니다.

## 10회 명중 · 투명인간과 공간 복원

같은 사람에게 10번 명중하면 그 사람의 윤곽만 사라지며 배경·다른 사람·검·HUD는 유지합니다. 사라진 자리에는 카메라에서 실제로 관측한 배경을 먼저 적용합니다. 아직 한 번도 보이지 않은 부분에는 주변의 완전한 배경 텍스처 조각을 찾아 경계에서 안쪽으로 이어 붙입니다. 반복 무늬는 수평 반복 간격을 측정해 타일·벽돌의 세로선이 사라지지 않도록 보완하고, 벽과 바닥이 만나는 행에서는 반복 간격을 다시 검증합니다.

**가장 정확하게 사용하려면 카메라를 고정하고, 시작 후 잠깐 화면 밖으로 나가 빈 공간을 1초 이상 보여준 뒤 돌아오세요.** 이때 실제로 관측한 빈 배경이 기억되므로 그 공간을 그대로 사용할 수 있습니다. 사람이 사라진 후에도 배경 학습은 계속되며, 움직여 새로 드러난 실제 배경은 추정 텍스처보다 우선합니다. 인물·머리카락·흐린 윤곽 주위는 여유를 두고 제외하고 두 번 연속 배경으로 확인한 픽셀만 학습합니다.

카메라에 보이지 않았던 가구나 글자 등을 정확하게 복구하는 3D 공간 인식/생성 모델은 아닙니다. 처음부터 사람이 가린 부분은 주변 무늬에 따른 추정입니다. 큰 카메라 이동이나 장면 변화가 확인되면 이전 배경을 버리고 새로 학습합니다. 작은 카메라 이동, 그림자, 가는 머리카락과 분할 오류에는 잔상이 생길 수 있습니다. 사람끼리 붙어 있으면 분할 모델이 하나의 윤곽으로 인식할 수 있습니다.

보관된 배경 투명 인물 컷아웃과 `모습 AR 배치` 기능도 유지합니다. 배경과 인물은 페이지 메모리에서만 처리하며 카메라 종료/초기화/예제 전환 시 배경 학습과 처리 작업을 정리합니다.

## 모델과 애니메이션 근거

사용자 첨부 검/화면을 시각적 기준으로 보고, 실제 텍스처는 Mojang 공식 `bedrock-samples`의 16×16 다이아몬드 검을 사용했습니다. 픽셀마다 앞/뒤 면을 만들고 투명 영역과 접한 부분에만 두께 1/16 블록의 옆면을 만듭니다. 모든 면을 단일 정적 indexed BufferGeometry로 병합합니다. 평면 사진을 회전시키는 빌보드가 아닙니다. 손은 공식 Steve 텍스처의 오른팔 UV를 사용합니다.

웹 조사에서 확인한 1차 자료:

- [Mojang 공식 1인칭 공격 애니메이션](https://github.com/Mojang/bedrock-samples/blob/15701fa9c13923f12662984c32c124327e40e3d3/resource_pack/animations/player_firstperson.animation.json): `first_person.attack_rotation`의 이동/회전 곡선.
- [Mojang 공식 플레이어 변수](https://github.com/Mojang/bedrock-samples/blob/15701fa9c13923f12662984c32c124327e40e3d3/resource_pack/entity/player.entity.json): 공격 진행도에 따른 사인 회전 인자. 이 예제는 이를 사용해 공격 시작/끝에 오프셋이 0이 되도록 인자를 연결합니다.
- [Microsoft Render Controllers](https://learn.microsoft.com/en-us/minecraft/creator/documents/animations/animationrendercontroller): entity의 hurt-color RGBA 표현.

위 곡선을 초 단위 진행도와 Three.js 좌표계로 옮기고, 0.30초 공격/0.50초 피격 구간 및 포인터 방향을 결합했습니다. 사람 영상에 맞게 빨간색 혼합 강도와 가장자리/종료 표현을 조정했습니다. 첨부 사진의 커스텀 HUD와 클래식 9칸 HUD는 구성이 달라 두 번째 사진을 핫바 기준으로 삼았습니다.

원본 게임의 에디션/버전/리소스팩/카메라 FOV/조명 전체를 실행해 비교한 것은 아닙니다. 공식 자료를 참조한 웹 재현이며 특정 게임 빌드와 프레임 단위로 완전히 같다고 검증하지 않았습니다. 텍스처의 원 저작권과 EULA 링크는 `public/minecraft/CREDITS.md`, 파일 해시는 `public/minecraft/provenance.json`에 기록합니다.

## 코드와 성능

- `src/scenes/minecraft-scene.ts`, `minecraft.css`: 카메라 동의, HUD/인벤토리, 입력과 정리.
- `src/minecraft-model.ts`: 공격 시간, 방향, 명중과 피격 시간, 공격 곡선.
- `src/minecraft-sword.ts`: 텍스처 로딩, 실제 두께를 가진 3D 픽셀 검, 팔 UV, 정적 HUD.
- `src/minecraft-renderer.ts`: 카메라/사람 피격 합성과 3D 손/검의 분리 렌더링.
- `src/minecraft-segmenter.ts`, `minecraft-worker.ts`, `minecraft-vision.ts`: 기존 로컬 SelfieSegmenter 모델만 사용하는 별도 세션. 기존 카메라 예제의 인식 설정을 변경하지 않습니다.
- `src/minecraft-capture.ts`: 같은 프레임의 인물 컷아웃과 실제 배경의 누적 학습, 장면 변경 시 무효화, 새 관측값 우선 합성.
- `src/minecraft-inpaint.ts`, `minecraft-inpaint-worker.ts`: 관측한 패치만 사용하는 주변 텍스처 복원. [패치 검색·전파 방식의 참고 연구](https://gfx.cs.princeton.edu/pubs/Barnes_2009_PAR/)를 참고한 제한된 탐색이며, 원본 PatchMatch 전체 구현이나 신경망 모델은 아닙니다.

Worker CPU 우선, 메인 GPU→CPU 호환 경로를 제공합니다. 한 번에 한 프레임만 분석하고 비트맵을 전달 후 종료합니다. Worker 입력은 가로 512px, 분석 간격은 최소 80ms(메인 최소 120ms)이며 실제 추론 시간에 따라 조절합니다. 카메라는 기존 공용 함수로 960×540/최대 30fps를 요청합니다. 손/얼굴 인식 모델은 추가 로딩하지 않습니다.

사람 마스크는 RG 8bit GPU 텍스처에 원래 윤곽과 투명 효과용 확장 윤곽을 함께 넣고, 크기가 같으면 버퍼를 재사용합니다. 확장은 대상이 사라진 이후 추론 결과가 올 때만 수행합니다. 화면 픽셀마다 여러 번 윤곽을 읽지 않고 한 번의 텍스처 읽기로 피격/사라짐을 구분합니다. HUD는 184×53 캔버스에 한 번 그린 뒤 pixelated 확대합니다. 검과 팔은 정적 메시 각 하나입니다. 화면 렌더링은 새 영상/공격/피격/상태/리사이즈가 있을 때 수행하며 카메라 OFF + 애니메이션 종료 시 rAF도 멈춥니다. DPR 최대 1.5, 버퍼 최대 1600×1200입니다.

배경 학습은 긴 변 최대 512px·최대 5Hz입니다. 텍스처 복원은 사라질 때와 충분한 새 배경이 관측되었을 때만 별도 Worker에서 처리합니다. 동시에 한 건만 수행하고 재처리 간격은 최소 1.2초입니다. Worker가 불가능한 환경에서는 같은 계산을 짧게 나누어 실행합니다. 탭 숨김/카메라 종료/초기화 때 Worker와 대기 타이머를 취소하고 오래된 결과를 적용하지 않습니다. 합성용 GPU 텍스처도 같은 캔버스와 크기라면 재생성하지 않고 갱신합니다. 추가 AI 모델과 외부 영상 전송은 없습니다.

탭 숨김 시 rAF/카메라 트랙과 사람 효과를 멈춥니다. 예제 전환과 카메라 종료에는 진행 중 초기화의 세대 번호 확인, 모델/Worker/타이머 정리, 트랙 종료를 적용합니다. 예제 종료에는 이벤트, ResizeObserver, 비트맵, GPU 텍스처/메시/컨텍스트를 정리합니다. 카메라 프레임은 네트워크로 전송하지 않습니다.

## 검증

2026-11-19: `npm.cmd exec tsc -- --noEmit`, `npm.cmd run build` 통과(종료 코드 0). 새 씬/CSS/Worker의 지연 로딩과 gzip/Brotli 생성을 확인했습니다.

같은 날 공간 복원을 보완한 뒤 서버 없이 `node --test tests/minecraft-inpaint.test.mjs`의 6개 픽셀 검증을 통과했습니다(Node 26.13.0의 TypeScript 직접 로딩 사용). 실제 관측 픽셀 보존, 벽/바닥 전환의 반복 무늬 복원, 화면 가장자리에 닿은 가림, 불규칙 텍스처의 인물 RGB 유출 방지, 전체 가림/작은 영상, 중도 취소 시 원본 보존을 확인합니다. 합성한 512×288 영상의 비교 이미지를 직접 확인해 색 확산보다 무늬가 유지되는 것을 점검했습니다. 실제 카메라/휴대폰에서의 품질·성능을 검증한 수치는 아닙니다. 전체 테스트 명령은 일부 기존 테스트가 Vite 서버를 자동 생성하므로 실행하지 않습니다.

정적 검사 통과: 예제 ID 15개와 각 mount/아이콘 연결, 접근성 이름, 기존 기본 경로, 로컬 사람 분할 모델을 확인했습니다. 텍스처 4개의 SHA-256이 provenance 및 dist 복사본과 일치합니다. 원본 검은 불투명 픽셀 84개와 노출 경계 80개로 검 메시의 삼각형은 496개입니다. 팔과 합쳐도 약 508개로 유지합니다. 기존 Three.js 공통 청크의 500kB 경고는 남아 있습니다.

개발 서버/미리보기 서버는 실행하지 않았습니다. 실제 카메라 분할 정확도, 실기기 WebGL 표시/입력/프레임/발열과 원본 게임의 프레임별 모션 동일성은 아직 직접 확인하지 않았습니다.
