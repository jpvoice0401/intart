## 실행과 사용

개발 서버는 사용자가 터미널에서 실행합니다.

```powershell
npm.cmd run dev
```

브라우저에서 `https://localhost:5174/?example=rubberhuman`을 열거나 상단의 늘어나는 얼굴 아이콘을 선택합니다.

1. 카메라를 켜고 얼굴 전체를 화면에 보여주세요. 처음에는 손을 얼굴에서 치워두면 가려지지 않은 얼굴 텍스처와 볼 색을 얻을 수 있습니다.
2. 얼굴 위에서 엄지와 검지를 맞대면 두 손끝 사이 지점에 얼굴이 잡힙니다. 집은 상태로 얼굴 안쪽으로 들어와도 접촉 지점에서 잡힙니다.
3. 손을 움직이면 해당 부분이 곡선으로 늘어납니다. 두 손으로 서로 다른 두 지점을 잡을 수 있습니다.
4. 엄지·검지를 벌리면 얼굴이 탄력 있게 튕기며 원래 자리로 돌아옵니다.
5. 카메라 화면의 얼굴을 마우스/터치로 눌러 끌어도 같은 효과가 동작합니다. 포인터 캡처로 화면 밖 이동/취소를 처리합니다.
6. `RESET`은 즉시 원상 복구, `Aa`는 설명 표시 전환, `CAMERA OFF`는 카메라와 모델 종료입니다.

## 구현

- `src/rubber-human-model.ts`: 핀치 히스테리시스, 변형된 표면의 삼각형 내부 좌표로 접촉 판정, 양손 앵커, 복귀 스프링, 얼굴 곡면.
- `src/rubber-human-renderer.ts`: 실시간 거울 카메라 → 원래 얼굴의 피부색 덮개 → 늘어나는 얼굴 텍스처 순서의 WebGL 렌더링.
- `src/rubber-human-models.ts`: MediaPipe HandLandmarker 2손, FaceLandmarker 1얼굴. 기존 로컬 모델과 WASM을 재사용하고 별도 모델을 다운로드하지 않습니다.
- `src/rubber-human-worker.ts`, `rubber-human-vision.ts`: 두 모델이 같은 입력 프레임을 분석합니다. Worker CPU 경로를 우선하고 실패 시 메인 스레드 GPU/CPU 경로로 전환합니다.
- `src/scenes/rubber-human-scene.ts`, `rubber-human.css`: 예제 UI, 동의, 상태와 생명주기.

얼굴 외곽은 36개 FaceLandmarker 윤곽점을 Catmull–Rom 곡선으로 보간합니다. 128개 각도 × 28개 반지름 고리와 중심점으로 **정점 3,585개, 삼각형 7,040개**를 만듭니다. 랜드마크를 그대로 큰 삼각형으로 잡아당기지 않습니다.

늘림은 부드러운 지지 영역을 가진 이동 벡터장을 작은 단계로 따라가도록 적분합니다. 긴 당김을 한 번의 선형 변위로 처리할 때 발생하는 면 접힘을 줄입니다. 양손 영향이 겹치면 결합 계수를 풀고, 손이 교차하거나 거의 겹치는 특이점에서는 단계 크기를 제한합니다. 극단적으로 가까운 양손 접촉에서는 정확한 두 지점 일치보다 안정성을 우선합니다.

앵커는 얼굴의 로컬 좌표에 저장하고 손 목표는 카메라 좌표에 유지하므로 얼굴 이동/회전에도 잡힌 점의 위치를 다시 계산합니다. 핀치 거리는 손바닥 크기로 정규화하며 닫힘 0.30/열림 0.48 비율로 떨림을 억제합니다. 좌우 거울 반전과 화면 cover 크롭은 렌더링과 포인터 입력에 동일하게 적용합니다.

잡고 있는 동안과 복귀 중에는 얼굴 텍스처를 고정합니다. 손이 얼굴 영역을 가리지 않는 프레임으로 텍스처를 갱신하고, 같은 시점의 UV를 보관해 얼굴을 따라 붙입니다. 배경 카메라는 계속 실시간입니다. 카메라 시작부터 얼굴이 손으로 가려져 있으면 첫 텍스처에도 손이 들어갈 수 있습니다.

원래 얼굴에는 50/101/205, 280/330/425번 볼 랜드마크 주변의 작은 피부 패치에서 얻은 색의 중앙값을 사용합니다. 손에 가려진 패치는 제외하고 색 변화는 완만하게 반영합니다. 덮개는 눈·코·입 영상을 전혀 샘플링하지 않는 두 볼 색의 연속 보간이며, 이목구비가 있는 내부를 불투명하게 가립니다.

테두리 수정: 피부색 덮개를 얼굴보다 6% 넓히던 처리를 제거했습니다. 원래 얼굴 경계 안에서만 그리고 정규화 반지름 0.76–0.94 사이에서 피부색을 카메라로 부드럽게 연결합니다. 늘어나는 얼굴 텍스처는 0.90–1.00 사이에서 페더링합니다. 잡기만 하고 실제로 당기지 않았거나 복귀가 끝난 상태에서는 합성 레이어를 숨겨 원본 카메라와 일치하게 합니다. 당김 시작과 끝은 얼굴 크기에 대한 변위 비율로 부드럽게 전환합니다.

## 성능과 정리

- 추가 분할 모델/제스처 분류기를 로딩하지 않습니다. 입력 영상의 분석 크기는 Worker 경로에서 가로 640px입니다.
- 한 번에 한 프레임만 분석하고 대기열을 만들지 않습니다. Worker 최대 약 15Hz, 메인 스레드 최대 약 9Hz이며 실제 추론 시간에 따라 간격을 늘립니다. 비트맵 리사이즈 미지원 시 원본 비트맵으로 재시도합니다.
- 그리기 버퍼는 가로 최대 1600px/세로 최대 1200px, DPR 최대 1.5로 제한합니다. 볼 색 샘플링은 약 6Hz, 깨끗한 얼굴 캡처는 최대 약 8Hz이며 잡기/복귀 중에는 다시 캡처하지 않습니다.
- 얼굴의 기본 곡면은 새 인식 결과가 올 때만 계산하고, 정점/인덱스/GPU 버퍼는 재사용합니다. 스프링은 최대 8ms 단위로 적분합니다.
- 손 추적이 300ms 넘게 끊기거나 얼굴이 350ms 넘게 끊기면 잡기를 해제합니다. 포인터는 누르는 동안 움직이지 않아도 유지합니다.
- 숨겨진 탭에서는 rAF와 카메라 트랙을 멈추고 잡기를 해제합니다. 예제 전환/카메라 종료 중 진행 중인 초기화도 취소합니다. 종료 시 모델, Worker, 타이머, 비트맵, 트랙, 텍스처/버퍼/WebGL 컨텍스트, 이벤트와 ResizeObserver를 정리합니다.
- 카메라 영상과 피부색 샘플은 서버로 전송하거나 파일로 저장하지 않습니다.

### 비주얼을 유지하는 실행 부하 최적화

2026-11-19: 고무 인간 예제에만 적용했습니다. 정점 3,585개/삼각형 7,040개, 영상·텍스처 해상도, 그리기 버퍼 한도, MediaPipe 옵션과 분석 간격, 핀치 임계값, 스프링 계수, 변형 적분 단계와 경계 블렌딩 값을 유지합니다.

- 모델에 기본 곡면/변형 정점 변경 번호를 두고, 새 입력이나 변형 없이 같은 곡면을 다시 계산하는 작업을 생략합니다. 접촉 판정 직전에는 필요한 곡면 갱신을 먼저 수행합니다.
- 매 프레임 생성하던 당김 목록·복귀 목록·변위 배열·최대 48단계의 벡터장 객체를 재사용합니다. 계수 버퍼는 JavaScript 숫자와 같은 정밀도의 Float64Array입니다. 얼굴 랜드마크 객체도 재사용하고, 외곽 곡선의 샘플 위치/인덱스를 한 번만 계산합니다.
- 기본 곡면 정점과 UV는 같은 GPU 버퍼를 공유합니다. GPU 정점 업로드는 해당 데이터의 변경 번호가 달라질 때, 합성 레이어가 보이는 경우에만 수행합니다.
- Three.js VideoTexture가 이미 받는 새 영상 프레임 알림을 재사용합니다. 새 카메라 프레임도, 변형/피부색/합성 상태/화면 크기 변화도 없으면 GPU 재그리기를 생략합니다. 해당 API가 없는 브라우저는 기존 video.currentTime 경로를 유지합니다. 당김과 탄성 복귀는 계속 rAF에 맞춰 갱신합니다.
- 카메라 OFF에서는 rAF 루프와 반복 화면 지우기를 중단하고, 카메라 시작/탭 복귀 시 다시 예약합니다. 카메라 OFF 상태의 화면 크기 변경은 ResizeObserver에서 처리합니다.
- 볼 색 채널 배열과 Vector3를 재사용하고 얼굴 경계는 새 인식 결과가 올 때 갱신합니다. 샘플링 간격, 같은 볼 패치의 중앙값, 가림 판정과 보간 방식은 유지합니다.
- 비트맵 리사이즈 옵션 미지원 여부를 기억하여 같은 프레임마다 실패/재시도를 반복하지 않습니다. Worker 단일 프레임 처리와 GPU/CPU 호환 경로는 유지합니다.
- 동일한 상태 문구를 DOM과 aria-live에 반복 대입하지 않습니다. 무손실 gzip/Brotli 빌드 압축은 기존 설정을 사용합니다.

최적화 전후 공용 메뉴와 다른 예제 소스의 SHA-256 집계가 일치하고, 고무 인간의 5개 셰이더 문자열도 동일함을 정적으로 확인했습니다. 이 검사는 셰이더 표현과 수정 범위를 확인하는 것이며 실기기의 전체 픽셀 비교나 성능 측정을 대신하지 않습니다.
